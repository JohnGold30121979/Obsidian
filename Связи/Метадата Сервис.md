# MetadataService - Обзор сервиса метаданных

  

## Общее описание

  

`MetadataService` - это центральный сервис, который управляет метаданными системы BIS.ERP. Он отвечает за:

- Управление справочниками (каталоги)

- Управление документами

- Создание и обновление таблиц в базе данных

- Генерацию номеров документов

- Выполнение автоматических расчетов

- Создание бухгалтерских проводок

  

## Основные компоненты

  

### 1. Метаобъекты (MetadataObject)

  

Основная сущность, которая описывает любой объект системы:

  

```csharp

public class MetadataObject

{

    public Guid Id { get; set; }

    public string Name { get; set; }           // "Счета-фактуры", "Кассы", "Организации"

    public string TableName { get; set; }      // "doc_invoices", "catalog_cash_desks"

    public string ObjectType { get; set; }     // "Document" или "Catalog"

    public string Description { get; set; }

    public string Icon { get; set; }

    public int Order { get; set; }

    public bool IsSystem { get; set; }

    public List<MetadataField> Fields { get; set; }

    public List<MetadataCalculation> Calculations { get; set; }

    public List<MetadataPostingRule> PostingRules { get; set; }

}

```

  

### 2. Поля (MetadataField)

  

Описание полей объектов:

  

```csharp

public class MetadataField

{

    public Guid Id { get; set; }

    public string Name { get; set; }           // "Номер", "Дата", "Сумма"

    public string DbColumnName { get; set; }   // "doc_number", "doc_date", "amount"

    public string FieldType { get; set; }      // "String", "Int", "Decimal", "DateTime", "Bool"

    public int Length { get; set; }

    public int Precision { get; set; }

    public int Scale { get; set; }

    public bool IsRequired { get; set; }

    public bool IsUnique { get; set; }

    public int Order { get; set; }

}

```

  

## Основные методы

  

### Инициализация системы

  

#### `InitializeDefaultMetadataAsync(Guid infoBaseId)`

Создает базовые документы системы:

- Приход товаров

- Расход товаров

- Проводки (бухгалтерские)

- Кассовые ордера (универсальные)

- Платежные поручения

  

```csharp

var documents = new List<MetadataObject>

{

    new MetadataObject { Name = "Приход товаров", TableName = "doc_incoming", ... },

    new MetadataObject { Name = "Расход товаров", TableName = "doc_outgoing", ... },

    new MetadataObject { Name = "Проводки", TableName = "doc_postings", ... },

    // ... другие документы

};

  

await _context.Set<MetadataObject>().AddRangeAsync(documents);

await _context.SaveChangesAsync();

  

// Создает таблицы для каждого документа

foreach (var doc in documents)

{

    await CreateTableForCatalogAsync(doc);

}

```

  

#### `InitializePredefinedCatalogsAsync(Guid infoBaseId)`

Создает предустановленные справочники:

- Организации

- Сотрудники

- Основные средства

- План счетов

- Кассы

- Банки

- Материалы

- Валюты

- Налоги

- И многие другие...

  

### Работа с данными

  

#### `GetCatalogDataAsync(Guid catalogId)`

Получает все записи из справочника:

  

```csharp

// Пример: получение списка организаций

var organizations = await _metadataService.GetCatalogDataAsync(catalogId);

  

// Возвращает List<Dictionary<string, object>>

// Каждый словарь - это одна запись

foreach (var org in organizations)

{

    string name = org["name"].ToString();

    bool isActive = (bool)org["is_active"];

    // ...

}

```

  

#### `CreateDynamicRecordAsync(Guid metadataId, Dictionary<string, object> data)`

Создает новую запись в документе или справочнике:

  

```csharp

// Пример: создание счета-фактуры

var invoiceData = new Dictionary<string, object>

{

    ["Номер"] = "1",

    ["Дата"] = DateTime.Today,

    ["Организация"] = orgId,

    ["Сумма"] = 1000m

};

  

Guid invoiceId = await _metadataService.CreateDynamicRecordAsync(invoiceMetadataId, invoiceData);

```

  

**Что происходит внутри**:

1. Проверяет и нормализует номер документа

2. Проверяет уникальность номера

3. Создает SQL INSERT запрос

4. Выполняет вставку

5. Выполняет автоматические расчеты (если есть)

6. Создает проводки (если нужно)

  

#### `UpdateDynamicRecordAsync(Guid metadataId, Guid recordId, Dictionary<string, object> data)`

Обновляет существующую запись:

  

```csharp

await _metadataService.UpdateDynamicRecordAsync(

    invoiceMetadataId,

    invoiceId,

    updatedData

);

```

  

**Что происходит внутри**:

1. Нормализует номер документа

2. Проверяет уникальность (если номер изменился)

3. Сохраняет предыдущие данные (для отката проводок)

4. Выполняет UPDATE

5. Пересчитывает проводки если документ был проведен

  

### Нумерация документов

  

#### [[GetNextDocumentNumberAsync]](MetadataObject document)`

Генерирует следующий номер для документа:

  

```csharp

// В InvoiceService

public async Task<string> GenerateDocumentNumberAsync()

{

    var metadata = await _context.MetadataObjects

        .FirstOrDefaultAsync(item => item.Name == "Выписка счет-фактур");

    return await _metadataService.GetNextDocumentNumberAsync(metadata);

}

```

  

**Процесс**:

1. Проверяет существует ли запись в `doc_numbering` таблице

2. Если нет - создает с начальным номером

3. Читает текущий номер

4. Инкрементирует и сохраняет обратно в БД

5. Возвращает текущий номер

  

### Проведение документов

  

#### `PostDocumentAsync(Guid documentId, Guid recordId)`

Проводит документ (создает проводки):

  

```csharp

await _metadataService.PostDocumentAsync(invoiceId, invoiceRecordId);

```

  

**Что происходит**:

1. Загружает метаданные документа

2. Загружает данные записи

3. Проверяет не проведен ли уже

4. Определяет тип документа

5. Вызывает соответствующий метод:

   - `ProcessCashOrderAsync()` - для кассовых ордеров

   - `ProcessPaymentOrderAsync()` - для платежных поручений

   - `ProcessDocumentByPostingRulesAsync()` - для других документов

6. Создает проводки в таблице `doc_postings`

7. Обновляет статус документа (`is_posted = true`)

  

#### `UnpostDocumentAsync(Guid documentId, Guid recordId)`

Отменяет проведение документа:

  

```csharp

await _metadataService.UnpostDocumentAsync(invoiceId, invoiceRecordId);

```

  

**Что происходит**:

1. Проверяет проведен ли документ

2. Удаляет проводки из `doc_postings`

3. Обновляет статус (`is_posted = false`)

  

### Автоматические расчеты

  

#### `ExecuteAutoCalculationsAsync(Guid metadataId, Guid recordId)`

Выполняет автоматические расчеты:

  

```csharp

// Пример: автоматический расчет суммы

var calc = new MetadataCalculation

{

    CalculationType = "Sum",

    SourceFields = "[\"Price\", \"Quantity\"]",

    TargetField = "Amount",

    IsAuto = true

};

  

await _metadataService.ExecuteAutoCalculationsAsync(documentId, recordId);

```

  

**Поддерживаемые типы расчетов**:

- `Sum` - сумма полей

- `Average` - среднее значение

- `Formula` - вычисление по формуле

- `Depreciation` - амортизация ОС

  

### Управление таблицами

  

#### `CreateTableForCatalogAsync(MetadataObject catalog)`

Создает таблицу в БД на основе метаданных:

  

```sql

CREATE TABLE IF NOT EXISTS "doc_invoices" (

    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    "doc_number" VARCHAR(50) NOT NULL,

    "doc_date" TIMESTAMP NOT NULL,

    "amount" DECIMAL(18,2) NOT NULL,

    "organization_id" UUID,

    -- ... другие поля

    "CreatedAt" TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    "UpdatedAt" TIMESTAMP DEFAULT CURRENT_TIMESTAMP

);

```

  

#### `UpdateTableStructureAsync(MetadataObject catalog)`

Обновляет структуру таблицы (пересоздает):

  

```csharp

// Используется при изменении структуры справочника

await _metadataService.UpdateTableStructureAsync(updatedCatalog);

```

## Динамическая природа системы

  

### Ключевая особенность: Динамические таблицы

  

В отличие от статичных моделей (Models/InvoiceModels.cs), система использует **динамические таблицы**, создаваемые на основе метаданных:

  

```csharp

// Вместо жестко заданной модели:

public class Invoice

{

    public int Id { get; set; }

    public string Number { get; set; }

    // ...

}

  

// Используется универсальный подход:

public async Task<Dictionary<string, object>> GetRecordDataAsync(string tableName, Guid recordId)

{

    // SELECT * FROM doc_invoices WHERE Id = @recordId

    // Возвращает словарь с динамическими полями

}

```

  

### Преимущества:

1. **Гибкость** - можно добавлять поля без изменения кода

2. **Конфигурируемость** - пользователь может настроить структуру

3. **Масштабируемость** - поддержка разных типов документов

  

### Недостатки:

1. **Сложность отладки** - нет compile-time проверки

2. **Производительность** - дополнительный уровень абстракции

3. **Type Safety** - работа со строками вместо сильных типов

### Просмотр метаданных

  

```sql

-- Все документы

SELECT Name, TableName, ObjectType

FROM MetadataObjects

WHERE ObjectType = 'Document';

  

-- Все справочники

SELECT Name, TableName

FROM MetadataObjects

WHERE ObjectType = 'Catalog';

  

-- Поля документа

SELECT m.Name as Document, f.Name as Field, f.DbColumnName, f.FieldType

FROM MetadataObjects m

JOIN MetadataFields f ON m.Id = f.MetadataObjectId

WHERE m.Name = 'Выписка счет-фактур'

ORDER BY f.Order;

```

  

## Заключение

  

`MetadataService` - это ядро системы BIS.ERP, которое обеспечивает:

- ✅ Динамическое управление структурой данных

- ✅ Автоматическую генерацию номеров

- ✅ Проведение документов и создание проводок

- ✅ Автоматические расчеты

- ✅ Гибкость и конфигурируемость

  

**Важно понимать**:

1. Все таблицы (кроме системных) создаются динамически на основе метаданных

2. Нет строгой типизации на уровне БД - используется гибкая схема

3. Нумерация документов централизована в одной таблице

4. Проводки создаются автоматически по правилам

  

**Для разработки**:

- Все изменения структуры документов/справочников через MetadataService

- Не используйте прямые SQL манипуляции с таблицами

- Соблюдайте порядок операций (сначала метаданные, потом данные)

- Тестируйте на копии БД перед применением к production
