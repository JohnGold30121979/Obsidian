PaymentOrderDialog — это WPF-окно для создания и редактирования платежных поручений (исходящих и входящих). Компонент состоит из XAML-разметки (Views/Dialogs/PaymentOrderDialog.xaml, 148 строк) и код-behind (Views/Dialogs/PaymentOrderDialog.xaml.cs, 783 строки).

## Архитектура и назначение

**Тип**: Window (модальный диалог)
**Назначение**: бухгалтерская операция — платежное поручение с поддержкой валют, классификации и аналитики по счетам
**Режимы**: 
- Новый документ (editId = null)
- Редактирование (editId.HasValue)

**Ключевые особенности**:
- Динамическая видимость полей на основе аналитики счетов (AccountAnalyticsRegistry)
- Поддержка валютных операций с автоматическим расчетом курса
- Два типа платежа: Исходящее (оплата) / Входящее (поступление)
- Классификация платежей через справочник

## Структура XAML (600x760, CanResize)

**Обертка**: ScrollViewer (вертикальный скролл автоматический) — для маленьких экранов
**Grid**: 2 колонки (Label=160px, Field=*) + 17 строк

1. **DialogTitle** — заголовок окна (жирный, 16px)
2. **Номер** — TextBox (IsReadOnly=True, Background=LightGray) — генерируется системой

4. **Тип** — ComboBox: "Исходящее (оплата)" / "Входящее (поступление)"
5. **Организация** — Label + ComboBox (Visibility=Collapsed по умолчанию)
6. **Сотрудник** — Panel (Visibility=Collapsed) — Label + ComboBox
7. **Материал** — Panel (Visibility=Collapsed) — Label + ComboBox
8. **Банк** — Label + ComboBox (Visibility=Collapsed)
9. **Дебет** — Label + Grid(TextBox + Button "?") — выбор счета через AccountSelectionDialog
10. **Кредит** — Label + Grid(TextBox + Button "?") — выбор счета
11. **Сумма** — TextBox (по умолчанию "0")
12. **Валюта** — Label + ComboBox (Visibility=Collapsed)
13. **Сумма в валюте** — Label + TextBox (Visibility=Collapsed)
14. **Курс** — Label + TextBox (Visibility=Collapsed)
15. **Классификация платежа** — Label + Grid(TextBox + Button "?") — ReferenceSelectionDialog

17. **Примечание** — Label + TextBox (Height=60, Wrap)
18. **Кнопки** — Сохранить (зеленая, 110px) + Отмена (серая, 110px)

### Динамические панели:
- **EmployeePanel** и **MaterialPanel** — StackPanel с collapsible Grid внутри
- Все поля с Visibility=Collapsed управляются через `UpdateAccountControlledFieldsVisibility()`

## Ключевая логика код-behind

### Инициализация (InitializeAsync)
**Два конструктора**:
- Новый документ: DialogTitle="Добавление", DatePicker=Today, TypeCombo.SelectedIndex=0
- Редактирование: DialogTitle="Редактирование", загрузка по editId

**Алгоритм загрузки**:
1. Guard clauses: `_isDataLoaded`, `_isLoading`
2. Параллельная загрузка справочников через `Task.Run(() => LoadReferenceDataAsync())`
3. Если редактирование — загрузка данных документа
4. Если новый — генерация номера через `_metadataService.GetNextDocumentNumberAsync()` (с fallback)
5. `UpdateAccountControlledFieldsVisibility()` — финальная настройка видимости

### Загрузка справочников (LoadReferenceDataAsync)
Загружает и привязывает (через Dispatcher.Invoke):

**Организации** (каталог "Организации"):
- Field mapping: "Наименование"/"name"
- ReferencePickerControlFactory.AttachEditor с поиском по "Код организации", "Наименование"

**Банки** (каталог "Банки"):
- Field: "Наименование банка"/"name"
- Аттач поиска

**Расчетные счета** (каталог "Расчетные счета организаций"):
- Специальная обработка: account_number + bank_name (через _banks.ToDictionary)
- DisplayName формат: "Счет - Банк"
- НЕ аттачит ReferencePicker (только загрузка данных)

**Валюты** (каталог "Справочник валют"):
- Формат: "Код - Наименование"
- Аттач поиска

**Сотрудники** (каталог "Сотрудники (Списочный состав)"):
- Display: "Табельный номер - ФИО"
- Аттач поиска

**Материалы** (каталог "Справочник материалов"):
- Display: "Код - Наименование материала"
- Аттач поиска

**Классификация платежей**:
- Загружается в `_paymentClassificationRows` (List<Dictionary<string, object>>)
- НЕ привязывается к ComboBox — используется через ReferenceSelectionDialog

### Загрузка документа (LoadDataAsync)
Чтение из каталога документа по Id:
- Номер: NormalizeLegacyDocumentNumber
- Дата, Сумма, Сумма в валюте, Курс, Назначение, Примечание
- Счета: TryGetRecordValue с фоллбеком по именам полей ("Наш счет", "our_account_id", "Дебет", "debit_account")
- ComboBox: SelectComboByRecordValue (Organization, Currency, Employee, Material)
- Классификация: ApplySelectedPaymentClassification
- Тип: парсинг строки "Входящее" → SelectedIndex=1

### Управление видимостью (UpdateAccountControlledFieldsVisibility)
**Алгоритм**:
1. Получить AccountAnalyticsRegistry settings для дебетового и кредитового счетов
2. Для каждого управляемого поля вызвать AccountAnalyticsRules.ShouldShowField():
   - **Организация**: если в настройках счета указан каталог "Организации"
   - **Валюта**: если указан "Справочник валют"
   - **Сумма в валюте/Курс**: зависит от того, показана ли Валюта
   - **Сотрудник**: если указан "Сотрудники (Списочный состав)"
   - **Материал**: если указан "Справочник материалов"
3. SetVisibility во所有 элементов (Label + Control)
4. При скрытии — сброс значения (ComboBox.SelectedItem = null, TextBox.Text = "0")

### Работа со счетами
**SelectOurAccount_Click / SelectCorrAccount_Click**:
1. Вызов SelectPlanAccountAsync(Action<Guid, string> applySelection)
2. Получение списка счетов через `_metadataService.GetChartOfAccountsSelectionDataForObjectAsync(_document.Id, _document.ObjectType)`
3. AccountSelectionDialog — выбор счета
4. ApplySelectedOurAccount/ApplySelectedCorrAccount:
   - Поиск в AccountAnalyticsRegistry по Id/accountValue
   - Установка _selectedOurAccountId/_selectedCorrAccountId
   - OurAccountBox.Text = account.Code
   - UpdateAccountControlledFieldsVisibility()

### Валютные расчеты
**OnRateInputChanged** (DatePicker + CurrencyCombo):
- LoadExchangeRateFromCatalogAsync:
  - Если валюта = KGS → курс=1, источник="Базовая валюта"
  - Иначе → GetCurrencyRateForDateAsync(currency.Id, documentDate)
  - Установка ExchangeRateBox.Text
  - RecalculateAmountFromCurrency()

**RecalculateAmountFromCurrency**:
- Amount = AmountCurrency * ExchangeRate
- Округление MidpointRounding.AwayFromZero до 2 знаков
- AmountBox.Text = результат

### Классификация платежей
**SelectPaymentClassification_Click**:
- Guard: _paymentClassificationRows.Count == 0 → предупреждение
- ReferenceSelectionDialog(_paymentClassificationRows, "Код", "Наименование")
- ApplySelectedPaymentClassification(value):
  - Поиск строки по Id
  - _selectedPaymentClassificationId = id
  - PaymentClassificationBox.Text = BuildDisplayName(row, "Код", "Наименование")

### Сохранение (OnSaveClick)
**Валидация**:
1. Номер: только цифры (NormalizeLegacyDocumentNumber + Any(char.IsDigit))
2. _selectedOurAccountId != Guid.Empty
3. _selectedCorrAccountId != Guid.Empty
4. Amount > 0

**Формирование itemData (Dictionary<string, object>)**:
- Обязательные: Номер, Дата, Тип (full documentType), Сумма, Назначение, Примечание, Проведён=false
- Условные (SetFieldValueIfExists — только если поле есть в метаданных):
  - Организация, Контрагент, Банк, Наш счет, Дебет, Расчетный счет контрагента, Счет контрагента, Валюта, Сумма в валюте, Курс, Сотрудник, Материал, Корр. счет, Кредит, Классификация платежа

**Сохранение**:
- Если _editId.HasValue → UpdateDynamicRecordAsync
- Иначе → CreateDynamicRecordAsync
- DialogResult = true, Close()

### Утилитарные методы
- **TryReadDecimal**: двойной парсинг (CurrentCulture + InvariantCulture)
- **SelectComboByRecordValue**: выбор ComboBoxItem по Guid.Id
- **SetFieldValueIfExists**: проверка наличия поля в метаданных документа перед добавлением
- **BuildDisplayName**: построение "Код - Наименование" с фоллбеком по альтернативным ключам
- **TryGetRecordValue**: получение значения по массиву возможных ключей

## Паттерн проектирования

**Hybrid approach**:
- Dialog-centric — Window с прямой работой с UI элементами
- Dynamic visibility — бизнес-правила аналитики счетов управляют видимостью
- Convention-based field mapping — попытки чтения полей по нескольким возможным именам (legacy-совместимость)

## Взаимодействие с сервисами

**MetadataService**:
- GetCatalogsAsync — справочники
- GetCatalogDataAsync — данные документов
- GetNextDocumentNumberAsync — генерация номеров
- GetCurrencyRateForDateAsync — курсы валют
- CreateDynamicRecordAsync/UpdateDynamicRecordAsync — CRUD
- AccountAnalyticsRegistry.LoadAsync — аналитика счетов

**AccountAnalyticsRegistry**:
- FindAccount(accountValue) — поиск счета по Id/коду
- GetSettingsById(accountId) — настройки аналитики для счета
- GetSettingsByCode(accountCode) — получение настроек по коду

**AccountAnalyticsRules**:
- ShouldShowField(fieldName, accountSettings, definitions, catalogName, ...) — правило отображения поля

**ReferencePickerControlFactory**:
- AttachEditor(comboBox, metadataService, catalog, owner, onItemsChanged, ...) — редактор с поиском

**ReferenceSelectionDialog** — для классификации платежей

## Особенности реализации

1. **Асинхронная загрузка**: Task.Run для справочников + Dispatcher.Invoke для UI
2. **Guard clauses**: _isLoading, _isDataLoaded для предотвращения двойной загрузки
3. **Legacy compatibility**: множественные варианты имен полей (Наш счет/our_account_id/Дебет/debit_account)
4. **Валютная панель**: появляется только при выборе валютного счета (через AccountAnalyticsRegistry)
5. **Автокурс**: автоматическая подстановка курса при смене даты/валюты (KGS всегда 1)
6. **Номер документа**: только цифры, нормализация legacy-форматов
7. **Динамическая форма**: Visibility полей определяется конфигурацией счетов, а не hardcoded
8. **Счета "за"?**: OurAccount (дебет) и CorrAccount (кредит) с валидацией непустоты
9. **Классификация платежей**: отдельный диалог выбора из справочника
10. **Проведён=false**: новые документы всегда создаются непроведенными

Диалог демонстри sophisticated подход к динамическим формам: видимость и состав полей определяется конфигурацией аналитики счетов, обеспечивая гибкость без изменения кода.
