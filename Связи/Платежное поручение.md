Модуль платежных поручений состоит из 3-х основных компонентов, связанных с навигацией, таблицей и формой редактирования.

**Архитектура модуля:**
1. Navigation → PaymentOrderWorkView (таблица)
2. PaymentOrderWorkView → PaymentOrderDialog (добавление/редактирование)
3. PaymentOrderDialog → PostDocumentAsync (проведение)

**1. MainWorkWindow.xaml.cs (регистрация в навигации)**

При построении дерева навигации (`CreateDocumentNavigationItem`) документ с именем "Платежное поручение" получает специальный тип `Type = "PaymentOrder"`. Затем обработчик `OnNavigationItemSelected` создаёт экземпляр `PaymentOrderWorkView(paymentDocument, _metadataService)` и переходит к нему через `_navigation.NavigateTo(paymentView)`.

**2. PaymentOrderWorkView (табличный список)**

Это UserControl-оболочка для просмотра списка платежных поручений. Содержит DataGrid с 17 колонками, 5 кнопок инструментов (Добавить, Редактировать, Удалить, Провести, Обновить) и статус-бар.

Ключевые особенности:
- Условные колонки (Организация, Валюта, Сумма в валюте, Курс, Сотрудник, Материал) показываются только если они реально используются в аналитике счетов проводок, иначе скрываются через `UpdateAnalyticColumns()`.
- При загрузке строится `referenceCache` — словарь `Guid → отображаемое имя` для всех справочников (организации, банки, сотрудники, материалы, валюты, классификация платежей), чтобы вместо GUID в таблице показывались понятные наименования.
- Специальная логика для поля "Наш счет": к номеру счета подставляется название банка в формате `"123456789 - Название банка"`.
- Поле "Корр. счет" ищется по нескольким возможным именам полей, затем резолвится через `AccountAnalyticsRegistry.FindAccount()`.
- При проведении вызывается `_metadataService.PostDocumentAsync()` — создаются бухгалтерские проводки.

**3. PaymentOrderDialog (форма документа)**

Это окно создания/редактирования платёжного поручения (~740 строк кода). Содержит:
- Номер (автогенерация через `GetNextDocumentNumberAsync()`)
- Дата, Тип (Исходящее/Входящее)
- Организация, Банк, Наш счёт (выбор через AccountSelectionDialog)
- Сумма, Валюта, Сумма в валюте, Курс (с автоматическим пересчётом: изменение валюты/курса → пересчёт суммы; изменение суммы в валюте → пересчёт суммы в сомах)
- Корр. счёт (выбор через AccountSelectionDialog)
- Классификация платежа (выбор через ReferenceSelectionDialog)
- Сотрудник, Материал (опционально, в зависимости от аналитики счетов)
- Назначение, Примечание

Ключевые механизмы:
- Загрузка справочников происходит в фоновом потоке (`Task.Run`), затем через `Dispatcher.Invoke` привязываются к ComboBox.
- Условная видимость полей (Организация, Валюта, Сотрудник, Материал) определяется через `UpdateAccountControlledFieldsVisibility()` на основе аналитики счетов: если счёт ведётся в разрезе организаций/валют/сотрудников/материалов — соответствующие поля показываются.
- Валютный блок (Валюта/Сумма в валюте/Курс) показывает/скрывается совместно.
- При сохранении вызываются `CreateDynamicRecordAsync` или `UpdateDynamicRecordAsync`.

**4. AccountAnalyticsRegistry + AccountAnalyticsRules (аналитика счетов)**

`AccountAnalyticsRegistry` загружает:
- Список счетов из "План счетов" с полями: код, наименование, тип счета, закрывающий модуль.
- Определения связей счетов со справочниками из каталога "Связи счетов со справочниками" (если каталог пуст/отсутствует — используются дефолтные связи для организаций, сотрудников, валют, материалов, участков, лицевых счетов, объектов строительства).
- Для каждого счета строится `AccountAnalyticsSettings` — набор активных связей на основе флагов в строке плана счетов.

`AccountAnalyticsRules` обеспечивает:
- `ShouldShowField` — определяет, нужно ли показывать поле документа в зависимости от выбранных счетов (например, если счёт не ведётся в валютном разрезе — скрыть "Валюта", "Сумма в валюте", "Курс").
- `IsAccountSelectorField` — проверяет, является ли поле бухгалтерским счётом (дебет/кредит/корр. счёт и т.д.).
- `GetAccountValueForField` — возвращает код счёта/ID для сохранения в документ.
- `ShouldShowFieldForRows` — агрегированная проверка для всех строк данных (для табличного вида).

**5. LocalizationService**

Отвечает за локализацию интерфейса и значений:
- Создаёт таблицу `LocalizationEntries` в БД при инициализации.
- Загружает дефолтные переводы (ru-RU, en-US) + пользовательские переводы из БД.
- `DisplayValue(object)` — универсальный метод для отображения булевых значений, статусов, типов счетов через локализацию (например, `true → "Да"`, `"active" → "Активный"`).
- `Translate(key)` — прямой перевод по ключу.

**6. ReferenceDisplayHelper**

Вспомогательный сервис для построения отображаемых значений справочников:
- `LoadMapsAsync` — строит карту `Guid → DisplayName` для всех reference-полей метаданных.
- `ResolveRows` — заменяет GUID на отображаемые имена в наборе строк.
- `BuildDisplayValue` — формирует строку отображения: сначала пытается использовать `DisplayPattern` с подстановкой полей, затем ищет стандартные поля ("Наименование", "ФИО", "Счет", "Код", "name", "code"), в крайнем случае возвращает Id.

**Поток данных:**
Навигация → PaymentOrderWorkView (загрузка всех данных, кэширование справочников, резолвинг аналитики) → PaymentOrderDialog (форма с авто-подстановками и условными полями) → сохранение → проведение (PostDocumentAsync) → обновление списка → PostingDetailsDialog (просмотр деталей проводки).
